# 01 — Modern C++ Baseline

**Goal:** Raise the language floor to **C++20** and replace bespoke
helpers with the standard library so the codebase reads like 2026 C++,
not 2005 C with classes.

## 1. Language standard bump

- Top-level `CMakeLists.txt` currently pins `CMAKE_CXX_STANDARD 11`.
  Bump to `20`.
- Keep `CMAKE_CXX_EXTENSIONS OFF`.
- MSVC floor: 19.38 (VS 2022 17.8) — supports `<format>`,
  `<ranges>`, `<span>`, `<bit>`, `<concepts>`, `<source_location>`.
- GCC floor: 12. Clang floor: 15.
- `legacy/` tree keeps building under C++20 (it already compiles
  under C++11/14/17 with no language extensions). Verified by the
  legacy CI matrix; no per-target downgrade.

### Steps

1. New round `R210-cxx20-bump`: change standard, run full build matrix,
   fix the small handful of breakage points (most likely
   `std::random_shuffle`, `std::iterator` base class, throw specs,
   `register` keyword, narrowing in aggregate init).
2. Add a compile-time guard in `src/v3/core/include/pvpgn/core/cxx.h`:
   `static_assert(__cplusplus >= 202002L, "pvpgn v3 requires C++20");`.
3. Document the floor in `README.md` and `docs/compile.*.md`.

## 2. Replace bespoke utilities with stdlib

| Bespoke | Standard | Where it lives today |
|---------|----------|----------------------|
| `src/v3/core/include/pvpgn/core/format.h` (fmt facade) | `<format>` + `std::format_to` | core/format |
| `core::Result<T,E>` | keep — std::expected still has rough edges in error_traits, BUT add `from_expected/to_expected` interop | core/result |
| custom `Span<T>` (if any) | `std::span<T>` | grep core |
| custom byte buffers | `std::vector<std::byte>` + `std::span<const std::byte>` | core/bytes |
| `pvpgn::core::Bytes` | thin alias over `std::vector<std::byte>`; keep helpers | core/bytes |
| handrolled endian swap | `<bit>` `std::byteswap` (C++23) — keep `core/endian.h` as polyfill until C++23 floor | core/endian |
| `printf`-style logging | `core::log::info("…", fmt-args)` already uses fmt; switch backend to `std::format` when MSVC perf parity reached | core/logging |
| `strtoul`/`atoi` parsing in protocol | `std::from_chars` | protocol/* |
| string trims / splits | `std::ranges::views::split` + `std::string_view` | core/string_utils |
| `std::iterator` CRTP | `std::ranges::iterator_t` / concepts | rare |

YAGNI gate: do **not** introduce coroutines, modules (`import std;`)
or `std::generator` until a concrete use case shows up. Tracked but
not scheduled.

## 3. Header hygiene

- Every public header in `src/v3/*/include/pvpgn/<lib>/*.h` must be
  **self-contained**: compiles standalone with `-Wall -Wextra -Wpedantic
  -Werror`. Add a `tests/unit/<lib>/headers_selfcontained.cpp` that
  `#include`s each public header in isolation (one TU per header,
  generated by a CMake helper `pvpgn_v3_add_header_selfcheck`).
- Forbid transitive convenience includes. No `<iostream>` in headers
  unless the header is a stream helper.
- Use IWYU (`include-what-you-use`) as a linter, not as a hard CI gate
  (false-positive rate is too high). See `12-build-tooling-ci.md`.

## 4. Style & idioms

- `final` on every concrete class that isn't a designed-for-extension
  port adapter.
- `[[nodiscard]]` on every `Result<T,E>`-returning function and every
  factory.
- Pass by value + `std::move` for sink parameters; pass by
  `std::string_view` / `std::span` for read-only views.
- No raw `new` / `delete` outside `infra/`. `core::make_unique`,
  `std::unique_ptr`, `std::shared_ptr` (only when shared ownership is
  genuinely required, which is rare in this codebase).
- Replace all remaining `NULL` with `nullptr` in v3 trees. Legacy tree
  is exempt until retired (see `14-legacy-retirement.md`).
- Replace `typedef` with `using` in v3 trees.
- Replace `enum` with `enum class` for every new enum; legacy enums
  migrate when the file they live in is touched.
