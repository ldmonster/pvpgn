# 02 — Repository Hygiene

## What

Delete files that are unused, redundant, or actively confusing. Move misplaced files. Reduce top-level noise.

## Why

A new contributor hitting `git clone` should see ≤ 20 entries at the top level and zero "what is this?" files.

## Concrete steps

### Top-level files to delete

| File | Reason |
|------|--------|
| `prompt.txt` | Author-local note; belongs in personal notes, not the repo. |
| `Makefile` | 20-line `cmake -B build` wrapper; presets do this better. |
| `.travis.yml` | Travis CI is dead; CI is on GitHub Actions + AppVeyor. |
| `docker-compose.yml` | Legacy compose; superseded by `docker-compose.v3.yml`. |
| `Dockerfile` | Legacy image; superseded by `Dockerfile.v3`. Rename `Dockerfile.v3` → `Dockerfile` after grace period. |
| `docker-compose.integration.yml` | Roll into `docker-compose.v3.yml` as a `--profile integration`. |

### `scripts/` cleanup

| File | Action |
|------|--------|
| `cvs2cl.pl` | Delete. CVS->CL converter from another era. |
| `convert_w3.pl`, `fsgs2bnetd.pl`, `flat2cdb.pl`, `lastlogin.pl`, `process.pl`, `reform.awk` | Delete; replaced by `pvpgn-migrate`. |
| `pvpgn_hash.inc.php`, `pvpgn_wol_hash.inc.php` | Move to a `contrib/` repo or delete. Not a PvPGN deliverable. |
| `S98bnetd`, `rc.bnetd`, `bnetd.init` | Keep only `bnetd.init` (systemd unit). Drop SysV / BSD rc. Add a `bnetd.service` systemd unit. |
| `tos.bat`, `tos.sh` | Delete. ToS is generated by the migrate CLI. |
| `xalloc_sweep.ps1` | Move to `scripts/dev/`; xalloc is being removed (see plan 05). |
| `cvs2cl.pl`, `make_testusers.sh`, `login_testusers.sh` | Move to `scripts/dev/`. |
| `localize/`, `sql/`, `storage/` | Keep; verify each script still references current schema. |

### `docs/` cleanup

| File | Action |
|------|--------|
| `compile.g++.md`, `compile.visualstudio2015.md` | Delete; consolidate into `docs/building.md` with presets. |
| `fdwatch.txt`, `storage.txt` | Convert to `.md`, link from index. |
| `alloc-survey.md`, `compat-survey.md` | Mark "historical"; move to `docs/history/`. |
| `migration-xalloc-to-stl.md` | Keep until xalloc removal lands; then move to `docs/history/`. |
| `readme.md` (lowercase) | Rename to `index.md` (mkdocs convention). |

### `build/` directories

- Add `build/` to `.gitignore` (already excluded from track, but make sure no `build/legacy/Release/*.exe` is committed by accident).
- Add a one-time CI job that fails if any path under `build/` is tracked.

### `src/common/` triage

`src/common/` is a graveyard. Per plan 05:

- Move `pugixml.cpp` / `pugixml.h` / `pugiconfig.h` to `vendor/pugixml/` and pull via CMake `add_subdirectory(vendor/pugixml)` or vcpkg `pugixml` port.
- Delete `xalloc.{cpp,h}` after callers migrate (see plan 05.2).
- Delete `scoped_array.h`, `scoped_ptr.h` (replaced by `std::unique_ptr`).
- Delete `asnprintf.{cpp,h}` (use `fmt::format`).
- Delete `fmt_compat.h` once C++20 `<format>` is universal in supported toolchains.

## Acceptance criteria

- [ ] Top-level file count ≤ 20.
- [ ] No file in `scripts/` is unreferenced by `Dockerfile`, CI, docs, or another script.
- [ ] `git grep -l xalloc src/` returns only `src/common/xalloc*` (until plan 05.2 lands).
- [ ] `mkdocs build --strict` passes.

## Risks

- Deleting `Makefile` may break downstream packagers. Mitigate: keep a one-line `Makefile` that prints the preset command for one release cycle, then delete.
- Renaming `Dockerfile.v3` → `Dockerfile` will break image pipelines pinned to `Dockerfile.v3`. Mitigate: keep a symlink/duplicate one release.

## Out of scope

- Removing `CREDITS`, `LICENSE`, `.editorconfig`, `.clang-format`, `.clang-tidy`, `.pre-commit-config.yaml`, `vcpkg.json`.
